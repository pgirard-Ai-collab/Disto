# PRD: Export Claude Skill

## Introduction

Ajouter une nouvelle destination dans la page System Prompt (vue agence et portail client) qui permet de télécharger le system prompt d'une marque sous forme de **Claude Skill** — un fichier `.zip` contenant un dossier `<brand-slug>/SKILL.md` au format officiel Anthropic Agent Skills. Cette destination s'ajoute aux quatre déjà présentes (ChatGPT Custom GPT, Claude Project, Gemini Gem, Universel) et se positionne juste après Claude Project pour regrouper l'écosystème Anthropic.

Un Claude Skill est composé d'un fichier `SKILL.md` avec un **frontmatter YAML obligatoire** (champs `name` et `description`) suivi du corps du prompt. Le champ `description` est critique : c'est ce que Claude lit pour décider d'invoquer le skill automatiquement.

## Goals

- Ajouter `claude_skill` comme nouveau `ExportFormat` valide côté API et UI.
- Générer un téléchargement `.zip` contenant `<brand-slug>/SKILL.md` avec frontmatter `name` + `description` auto-généré + body identique au format Claude Project.
- Positionner la nouvelle destination juste après « Claude — Project » dans le panneau d'export.
- Afficher des instructions d'installation pour Claude.ai (interface Skills) **et** Claude Code CLI (`~/.claude/skills/`).
- Réutiliser l'authentification, l'autorisation et la logique de récupération de structure publiée existantes.

## User Stories

### US-001: Ajouter `claude_skill` au type ExportFormat et à la liste valide
**Description:** En tant que développeur, je dois étendre le type `ExportFormat` et la constante `VALID_FORMATS` pour que l'API accepte le nouveau format sans rejet 400.

**Acceptance Criteria:**
- [ ] `ExportFormat` inclut `'claude_skill'` dans [app/api/export/route.ts](app/api/export/route.ts) et [app/(client)/[brand]/export/ExportPanel.tsx](app/(client)/[brand]/export/ExportPanel.tsx)
- [ ] `VALID_FORMATS` array inclut `'claude_skill'`
- [ ] `FORMAT_EXT` mappe `claude_skill` → `'zip'`
- [ ] Typecheck passes (`npm run typecheck`)

### US-002: Générer le contenu SKILL.md avec frontmatter et description auto-générée
**Description:** En tant qu'utilisateur, je veux que le SKILL.md téléchargé contienne un frontmatter YAML valide avec un `description` qui permet à Claude d'invoquer automatiquement le skill quand l'utilisateur interagit avec la marque.

**Acceptance Criteria:**
- [ ] Une fonction (ex. `buildClaudeSkillMarkdown(brandName, brandSlug, body, generatedAt)`) génère un string commençant par `---\nname: <brand-slug>\ndescription: <auto-generated>\n---\n\n`
- [ ] `name` est le `brand-slug` (kebab-case, minuscules, conforme au format Skills officiel)
- [ ] `description` est auto-généré au format : `"Réponds et communique comme la marque <brand-name>. À utiliser pour toute interaction de marque, copywriting, réponses client, et création de contenu nécessitant la voix de <brand-name>."`
- [ ] Le body suit immédiatement après le frontmatter et inclut le titre `# System Prompt — <brand-name>` et la note de génération, identique au format `claude_project` actuel
- [ ] Typecheck passes

### US-003: Empaqueter le SKILL.md dans un .zip côté serveur
**Description:** En tant qu'utilisateur, je veux télécharger un seul fichier `.zip` qui se déballe en un dossier prêt à être placé dans `~/.claude/skills/` ou uploadé sur claude.ai.

**Acceptance Criteria:**
- [ ] La route GET `/api/export?format=claude_skill` retourne un blob `application/zip`
- [ ] Le `.zip` contient une seule entrée : `<brand-slug>/SKILL.md`
- [ ] Nom du fichier téléchargé : `<brand-slug>-claude-skill.zip` (via header `Content-Disposition`)
- [ ] `Content-Type: application/zip`
- [ ] La création du zip utilise une lib Node native ou une dépendance minimale (ex. `jszip` ou `adm-zip` — privilégier celle déjà présente, sinon ajouter la plus légère)
- [ ] Typecheck passes

### US-004: Ajouter la destination Claude Skill au panneau ExportPanel
**Description:** En tant qu'utilisateur (admin ou client), je veux voir une carte « Claude — Skill » dans le panneau de destinations, positionnée juste après « Claude — Project ».

**Acceptance Criteria:**
- [ ] Nouvelle entrée dans `EXPORT_TARGETS` de [app/(client)/[brand]/export/ExportPanel.tsx](app/(client)/[brand]/export/ExportPanel.tsx) :
  - `format: 'claude_skill'`
  - `tag: 'Claude — Skill'`
  - `mark: 'SK'`
  - `color: '#F02D14'` (même rouge Anthropic que Claude Project)
  - `ext: '.zip'`
- [ ] L'entrée est positionnée à l'index 2 (juste après `claude_project`, avant `gemini_gem`)
- [ ] Le bouton « Télécharger » déclenche `handleExport('claude_skill')` et reçoit le `.zip`
- [ ] Le blob est sauvegardé avec le nom retourné par le header `Content-Disposition`
- [ ] Typecheck passes
- [ ] Verify in browser using dev-browser skill

### US-005: Rédiger les instructions d'installation (Claude.ai + Claude Code CLI)
**Description:** En tant qu'utilisateur, je veux savoir comment installer le skill téléchargé, à la fois dans claude.ai et dans Claude Code CLI.

**Acceptance Criteria:**
- [ ] Le champ `instructions` de la nouvelle entrée contient deux sous-sections en français, séparées visuellement (lignes vides + libellés en majuscules) :
  - **CLAUDE.AI :** étapes pour uploader le `.zip` via l'interface Skills (Settings → Capabilities → Skills → Upload)
  - **CLAUDE CODE CLI :** étapes pour déballer le `.zip` dans `~/.claude/skills/` puis redémarrer Claude Code
- [ ] L'accordéon « Instructions d'installation » s'ouvre/se ferme correctement comme pour les autres formats
- [ ] Mise en forme cohérente avec les instructions des autres destinations (`whiteSpace: 'pre-line'`)
- [ ] Verify in browser using dev-browser skill

### US-006: Vérification de bout en bout
**Description:** En tant que QA, je veux confirmer que le téléchargement fonctionne et que le skill est utilisable.

**Acceptance Criteria:**
- [ ] Téléchargement déclenche le download d'un `.zip` nommé `<brand-slug>-claude-skill.zip`
- [ ] Le `.zip` se déballe en `<brand-slug>/SKILL.md`
- [ ] `SKILL.md` commence par un frontmatter YAML valide (3 dashes, `name`, `description`, 3 dashes)
- [ ] Le contenu après frontmatter correspond au system prompt courant de la marque
- [ ] Les états `downloading`, `error`, et `!hasStructure` (bouton désactivé) fonctionnent comme pour les autres formats
- [ ] `npm run lint` et `npm run typecheck` passent
- [ ] Verify in browser using dev-browser skill

## Functional Requirements

- FR-1: Étendre `ExportFormat` (TypeScript) et `VALID_FORMATS` (runtime check) pour inclure `'claude_skill'` dans la route API et le composant client.
- FR-2: Mapper `FORMAT_EXT['claude_skill'] = 'zip'`.
- FR-3: Implémenter `buildClaudeSkillMarkdown(brandName, brandSlug, body, generatedAt)` qui retourne un string complet `SKILL.md` (frontmatter YAML + body).
- FR-4: Le `description` du frontmatter doit suivre le template : `Réponds et communique comme la marque <brand-name>. À utiliser pour toute interaction de marque, copywriting, réponses client, et création de contenu nécessitant la voix de <brand-name>.`
- FR-5: Le `name` du frontmatter doit être le `brand-slug` (déjà en kebab-case dans la table `clients.slug`).
- FR-6: Côté serveur, créer un `.zip` en mémoire contenant `<brand-slug>/SKILL.md` et le renvoyer avec `Content-Type: application/zip` et `Content-Disposition: attachment; filename="<brand-slug>-claude-skill.zip"`.
- FR-7: Côté UI, ajouter la nouvelle entrée à `EXPORT_TARGETS` en position 2 (après `claude_project`).
- FR-8: Côté UI, écrire les instructions d'installation pour claude.ai et Claude Code CLI dans le champ `instructions`.
- FR-9: Réutiliser le flux existant `handleExport()` — pas de logique de download spécifique au format zip (le blob et `Content-Disposition` font déjà le travail).
- FR-10: Conserver l'autorisation existante (`agency_admin` ou `client_users` actif pour la marque) sans modification.

## Non-Goals

- Pas de gestion de skills multiples par marque (un seul skill = le system prompt complet).
- Pas de ressources additionnelles dans le skill (pas de `scripts/`, `references/`, etc. — juste `SKILL.md`).
- Pas d'édition manuelle du frontmatter par l'utilisateur (auto-généré uniquement, conformément à 3A — un éventuel champ éditable est hors scope).
- Pas de signature, vérification d'intégrité, ou packaging avancé du skill.
- Pas de support pour le format Skills d'autres plateformes (ChatGPT, Gemini, etc.).
- Pas de modification du `buildPromptBody` ni du contenu du system prompt lui-même.

## Design Considerations

- Réutiliser le composant de carte de destination existant (`EXPORT_TARGETS.map(...)` dans [ExportPanel.tsx](app/(client)/[brand]/export/ExportPanel.tsx)) — aucun nouveau composant à créer.
- La pastille de format (`mark`) doit utiliser la même couleur rouge Anthropic (`#F02D14`) que Claude Project pour signaler l'écosystème commun, mais avec le libellé `SK` pour différencier.
- Aucun bouton « primary » (rouge plein) pour cette destination — seul ChatGPT garde ce traitement, les autres restent en bordure ghost.
- Les instructions d'installation utilisent `whiteSpace: 'pre-line'` ; séparer les deux sous-sections par une ligne vide et un libellé en majuscules pour la lisibilité.

## Technical Considerations

- **Création du zip** : vérifier si une lib zip est déjà présente dans `package.json`. Sinon, installer `jszip` (léger, fonctionne en Node et navigateur, API simple). Éviter `archiver` qui nécessite des streams Node et complique les Route Handlers de Next.js.
- **Encoding** : le `SKILL.md` doit être encodé en UTF-8 dans le zip (le contenu contient des caractères français).
- **Brand slug** : déjà disponible via `client.slug` côté API et `brandSlug` côté UI — pas de nouveau fetch nécessaire.
- **Réutilisation** : `buildPromptBody` et la logique d'auth restent inchangées ; toute la nouvelle logique tient dans : (a) un nouveau case dans `formatForPlatform` qui retourne le `SKILL.md` string, (b) une branche dans le handler GET qui construit le zip et change `Content-Type`.
- **Streaming** : pour un seul fichier texte, pas besoin de streaming — un `Buffer` retourné dans `new NextResponse(buffer, ...)` suffit.

## Success Metrics

- Le `.zip` téléchargé peut être placé tel quel dans `~/.claude/skills/` et Claude Code détecte le skill au prochain lancement.
- Le `SKILL.md` passe une validation YAML frontmatter standard (3 dashes, clés `name` + `description`, 3 dashes).
- Aucune régression sur les 4 destinations existantes (ChatGPT, Claude Project, Gemini, Universel).
- Le téléchargement complet (clic → fichier sur disque) prend moins de 2 secondes pour un prompt de taille typique (~5k tokens).

## Open Questions

- Faut-il limiter la taille du `description` du frontmatter ? La doc Anthropic recommande de garder ce champ concis (1-2 phrases) pour aider Claude à décider. Le template proposé fait ~30 mots — acceptable.
- Le `brand-slug` peut-il contenir des caractères non valides pour un nom de skill (ex. underscores) ? À vérifier au moment de l'implémentation — la table `clients.slug` semble déjà contraindre à du kebab-case mais à confirmer.
- Doit-on inclure un `README.md` à la racine du zip (hors dossier) expliquant comment installer ? Décision : non pour ce PRD (3A spécifie auto-généré minimal). Les instructions sont déjà dans l'UI.
